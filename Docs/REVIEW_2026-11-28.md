# Review of the work against the data (28 Nov 2026, evening)

Scope: the findings in [DATA_FINDINGS.md](DATA_FINDINGS.md), the runtime (`rover/`), tools, firmware, configs and the Phase E prediction for Tuesday's Tier 1 demo. Simulation numbers below are Tier 1, LQI, stationary beacon, s1 multipath unless stated; with 16–24 seeds the standard error of a success rate is about ±10 points.

## 1. Assessment of the findings

| Finding | Strength | What it implies |
|---|---|---|
| Acquisition, timing, alternation (E0, E4, latency) | **Solid**: deterministic, reproduced on three days, ≤ 1 ms | $T_m$, $T_\text{gap}$, $T_d$ are settled inputs; no further work |
| Range law $n = 1.01 \pm 0.02$, $K$ within 1.4 % across sessions | **Solid** on 1.0–1.5 m (3168 amplitudes, two sessions) | $K$ is a calibration of volume + trimmer, not of the room; one 1.0 m reference capture suffices after a level change |
| 0.75 m low, 2.0 m high | **Solid** (13 and 5 captures, all residuals one sign) but **mechanism open** | The range sensor saturates near 1.5 m indoors. The old simulator assumed a pure power law, so it could not see the consequences (§3) |
| Bearing: 12° fringe + 23° room bias, held-out 27.6° | **Medium**: 6 held-out poses, one training spot | Tier 1 only; and the calibration transfers poorly between spots (next row) |
| β = 0 reads −0.4° on the A2 spot but −7 … −25° elsewhere later the same day; ±13° drift within a static capture | **New, medium** | A spot- and time-dependent boresight error of the size of the room bias. The Tier 1 start spot needs its own zero check |
| Wall-adapter clipping (F1) | **Solid** (four isolation tests) | Battery-only practice is right; keep it |
| Listening while driving at volume 80 % + blanking | **Solid** for the lifted rover (186–187 pairs per run, 100 % valid) | Motors are not a sensing problem at that level; the motor-noise prediction was built on a wrong premise (§2) |
| Mic/servo wiring fault | **Open**, reproduced twice | The single largest risk for Sunday; not a modelling issue |
| Vehicle: steering, speed, $T_d$ | Steering and $T_d$ solid; speed table from 11 runs with a battery-LED drop 2 → 1 | Lags and braking still provisional; $v_\text{max}$ = 0.203 m/s leaves 0.023 m/s above the 0.18 m/s design speed |

## 2. Critical review: what the work got wrong, and the change made

| # | Issue | Evidence | Change (applied) |
|---|---|---|---|
| R1 | **Live $R$ used the raw in-band $N$ as the amplitude sd.** $N$ is the rms of one noise bin; a 16-tone power average has $\sigma_A \approx N/\sqrt{2M}$. | Motors raise $N$ 1.2 → 7.9 while sd($\sqrt{A_-A_+}$) stays 1.2–1.5 (DATA_FINDINGS §7.4). At volume 40 % the added bearing scatter is 10° on $A$ = 16.6, $N$ = 7.0 → effective scale 0.29. | `sensing.estimate`: $\sigma = \max(\sigma_\text{floor}, s\,N)$ with new key `noise_to_amplitude_sd` $s$ (default 1 = old behaviour; measured configs 0.30). |
| R2 | **The motor-noise prediction simulated the wrong noise.** It set the true amplitude noise to 8.0 counts; the measured motor-on scatter is 1.9. | Same data. | Simulator: new `sim_reported_noise` (the $N$ the firmware reports, read by $R$) separate from the true `amplitude_noise`. `measured_config_motor.json` now = true 1.9, reported 7.9. |
| R3 | **The simulator's range law was ideal.** No pose-to-pose range bias, no saturation beyond 1.5 m, no near-field deficit. | A2 + s1 E3 (§7.3). | `simulation.MultipathModel`: opt-in symmetric range field (`room_range_ln_sd`, 0.08) and `range_bias_table` (the 28 Nov residuals). Phase E's "s1 measured" level now includes both. Runs without these keys are bit-identical (tested). |
| R4 | **Tier 1 success in simulation used ±0.25 m**, the pre-registered criterion is ±0.2 m. | `NEXT_STEPS_SHORT.md` QW4 vs `phase_e.tier_outcome`. | `TIER1_TOLERANCE_M = 0.2`, stated in the report. |
| R5 | **Phase E reports claimed `Config/phase_e.json`** whatever config was used (the 16:26 measured runs too). | `REPORT.md` line 3 of every run. | Report names the actual `--config`, `amplitude_noise` and whether the speed table is measured. |
| R6 | **The bearing model has no re-zero path.** `load_config` forbids `boresight_deg ≠ 0` with a `bin_model`, so the −15 … −25° offsets seen off the A2 spot cannot be corrected without a full refit. | §7.5b. | `Tools/rezero_bin_model.py`: shifts every intercept $c_k \to c_k + s_k b$, which removes a constant offset $b$ exactly and keeps slopes and weights. A2 spot: $b$ = −0.4° (nothing to do); 15:42 floor spot: $b$ = −14.7°. |
| R7 | Runbook said the rover must stop to listen; the 28 Nov data and the decision say otherwise. | §7.4. | `Docs/ROOM_CALIBRATION.md` "Driving" rewritten: conditions (volume, battery, people ≥ 1 m away, zero check at the start spot). |
| R8 | Firmware docs called horn12 the default; the source default is wide16 (the profile everything is calibrated on). Blanking was undocumented. | `.ino`, firmware README. | Comments and README corrected; blanking documented. |

## 3. Updated Tier 1 prediction

| Case (16 seeds, start 2.0 m) | Success | Final range |
|---|---|---|
| 16:26 motor variant (true noise 8.0, ±0.25 m) | 62 % (8 seeds: 50 %) | 1.21 ± 0.08 m |
| Motors off, ±0.25 m, ideal range law (16:26 baseline) | 88 % (8 seeds: 100 %) | 1.09 ± 0.07 m |
| Motors off, **±0.2 m** | 81 % | 1.09 ± 0.07 m |
| Motors off, ±0.2 m, **measured range law** | **56 %** | 1.13 ± 0.35 m |
| Drive on ($N$ 7.9 reported, $s$ = 0.30), ±0.2 m, range law | 75 % | 1.12 ± 0.36 m |
| Drive on, raw $N$ in $R$ (old estimator), ±0.2 m, range law | 56 % | 1.30 ± 0.40 m |

- The systematic table alone costs nothing (81 %); the 8 % pose-to-pose range bias spreads the stop to 0.75–1.23 m (69 %).
- **Two new failure modes**, invisible to the old simulator: (a) at the 2.0 m start the reverberant floor plus a positive pose bias reads ρ̂ ≈ 1.04–1.16 and the stand-off latches at once (seed 3004, true 2.07 m); (b) room bias pushes the bearing error past the ±30° window and the follower never locks (seed 3007).
- **Start range** (24 seeds, full range law): 2.0 m → **54 %**, 1.75 m → **83 %**, 1.5 m → 67 %. Starting inside the accurate range domain removes failure (a).
- The motor-on prediction is no worse than motors-off once the noise is modelled as measured; with the old raw-$N$ estimator it stops 0.17 m further out on average.
- Full Phase E with the corrected models: [`20261128T173205_452622Z_phase_e`](../Runs/2026-11-28/20261128T173205_452622Z_phase_e/REPORT.md) (motors off: Tier 1 100 / 100 / 50 %) and [`20261128T173402_499488Z_phase_e`](../Runs/2026-11-28/20261128T173402_499488Z_phase_e/REPORT.md) (drive on: Tier 1 100 / 100 / 62 %). Tiers 2–3 at s1 stay at 0 % in both.

## 4. Bugs found and fixed

| Bug | Effect seen in the data | Fix |
|---|---|---|
| **First firmware command lost after the port-open reset** (garbage in the 32-byte line buffer) | `P`/`D` silently ignored; `?` answered late or never (`145922`: no `C2` line) | Leading `\n` before the commands in `collect`, `live`, `identify latency`, `pi_check`, `esp_logger` |
| **Captures recorded baud garbage for their full duration** | 12 of the 16 empty 28 Nov runs: 41–311 lines of pure noise at the 0.48 s pair cadence, 0 pairs, no warning; one more received nothing at all; the paired motor spins ran with no audio | New `rover/link.py`: handshake must deliver a valid `C2` or CRC-checked `R2` within 4 s, else close/reopen (3 attempts), then a `LinkError` naming the cause. Used by `collect` and `live` |
| **Port-open failures left an unexplained empty run** | 3 runs with only `session.json`/`summary.json` (`070617`, `110130`, `153923`) | `collect` writes the reason to `summary.json` (`error`) and exits with code 2; `capture_summary` prints it |
| Test suite only ran when copied to `Tests/` (resolved the repo as `Local/`) | 28 of 71 tests errored in place | Tests locate the repo root by the `rover` package; `create_run` also hashes `Local/Tests` |
| `capture_summary` crashed on an empty `Runs/`; its clip legend described the old firmware | — | Guarded; legend describes the firmware flag |
| Stale links: `README.md` → deleted `CONTROL_DESIGN.md`; `VALIDATION_STATUS.md` → `../Config` | — | Fixed |

Tests: 76 pass (71 existing + 5 new: handshake retry and leading newline, open-failure/garbage reporting, noise-scale default, simulator range terms opt-in and range-only, exact re-zero shift). `collect` smoke-tested against a missing port: fails in 3 s with the reason in `summary.json`. Not tested on the Pi or with the ESP32.

## 5. Recommended, not applied (need the hardware or your decision)

1. **Fix the mic/servo wiring before anything else** (multimeter on MAX4466 VCC/GND/OUT and servo V+/signal/GND); the two fault episodes would void a trial day.
2. **Start Tier 1 at 1.75 m, not 2.0 m** (54 → 83 % in simulation). This changes the pre-registered protocol, so decide it before the first run and state it on the slide.
3. **Zero check at the start line**: two 20 s captures at β = 0 (1.0 and 1.75 m), `Tools/rezero_bin_model.py`; apply with `--out` if |b| > 5°.
4. **Keep people ≥ 1 m from the rover and speaker** during runs; the operator stands behind the speaker.
5. Run the Tier 1 trials along the A2/s1 line (QW1): the range table and the bearing zero are measured there.
6. Flash the current firmware (blanking + comment changes) and `git pull` on the Pi: `collect`/`live` now need `rover/link.py`.
7. Consider a latch guard in `Tracker`: no stand-off latch before ρ̂ has decreased by ≥ 0.2 m or before N pairs, to remove failure mode (a) at any start range. Not applied: it changes the controller two days before the demo.
